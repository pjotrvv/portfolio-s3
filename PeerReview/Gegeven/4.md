### Code review
- Goed gebruik van dto

- assignment.controller.js op lijn 30 staat nog een console.log

- De api heeft geen validation in de backend. Als een check in de frontend niet goed zijn taak heeft gedaan, en er wordt bijvoorbeeld een string 
meegestuurd in een veld waar dat een integer moet zijn, dan zal hij altijd nog code 204 no-content terug geven: het is allemaal gelukt, maar er komt geen data terug.
Als er een check is in de backend die nog zorgt dat de data klopt, dan heeft die nu geen mogelijkheid om een error terug te geven aan de frontend.
In de frontend is er wel een complete check op wat er terug wordt gegeven door de api: als het json is, dan maakt de frontend er json van, en anders is het gwn raw text.
Maar als de server zelf altijd niks teruggeeft en altijd succesvol is, is dit toch niet nodig? Bovendien is het niet altijd zo dat alles goed gaat als je put, maar daar is geen error return in de server van.

- In de startrepo die door school was gemaakt heete de backend package counter. Dit is bij jullie nooit aangepast naar de goede naam voor jullie project.

- AssignmentController gebruikt in de post request (assignment maken) de class assignment uit het domain. Dit is een te grote stap en moet worden gedaan in de service laag. Bij de put uit de pull request wordt dit wel goed gedaan.
