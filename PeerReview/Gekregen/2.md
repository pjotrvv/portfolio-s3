## Backend – Domein & Architectuur
 
###  Domeinmodellering
- Vermijd het gebruik van *setters* in domeinmodellen. Gebruik in plaats daarvan *betekenisvolle update-methodes* met validatie- en domeinlogica.
- Verplaats de logica uit updateDeclaratie (regel 120) naar het domeinmodel. Services horen orchestration te doen, niet businesslogica.
- In het Declaratie-domein bevatten setters geen domeinregels. Zet alle wijzigingslogica in methodes binnen het domein.
- Controleer ook andere domeinen op het gebruik van setters.
 
###  Taalconsistentie
- Vermijd gemixte Nederlands/Engels in *namen, variabelen, properties en responses*.
- De volledige Declaratie-class moet herschreven worden naar *Engels*.
- Hetzelfde geldt voor de *hele codebase* (frontend én backend).
 
### Transactional gebruik
- Waarom staan er @Transactional annotaties op *GET-methodes*?
- @Transactional hoort alleen toegepast te worden op methodes die *wijzigingen uitvoeren* (CREATE/UPDATE/DELETE).

##  Frontend – Codekwaliteit & Consistentie
 
###  Naming & JSON Structuur
- Responses van de backend bevatten Nederlandse velden, waardoor de frontend-modellen ook Nederlands zijn.
- Gebruik *Engelse propertynamen* voor betere consistentie, schaalbaarheid en samenwerking.
 
###  Code Smells & Optimalisatie
- In ClaimDetails (regel 22–40): vervang de if / else if / else-structuur door *switch-case* of losse if statements voor betere leesbaarheid.
- Gebruik *constants* voor statuswaarden zoals AFGEKEURD en REJECTED in plaats van hard-coded strings.
- Verwijder alle console.log statements (o.a. in claim.page.js) uit productiecode.
 
###  Hard-coded values
- In onSubmitClaim (regel 118) is approver = Lionel Messi hard-coded.
- Deze waarde zou dynamisch moeten komen uit:
  - de backend,
  - de ingelogde gebruiker,
  - of configuratie.
 
###  DRY Principle
- In claim-form.js (regel 36–50) zijn twee if-statements bijna identiek:
  - file = null
  - showError = true
  - return false
  - Alleen de foutmelding verschilt.
- Refactor dit naar *één herbruikbare functie* met een variabele voor de foutmelding.
 
###  Form Handling Inconsistent
- In createClaim wordt *FormData* gebruikt, maar in onSubmit (regel 73–78) worden de waarden handmatig uit de DOM gehaald.
- Kies *één consistente aanpak* (bij voorkeur FormData).
